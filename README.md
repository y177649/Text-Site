# Text-Site

教材テキストを配布する静的サイトと、テキストが開かれた回数を記録する仕組み。

- **サイト**：`index.html` / `app.js` / `style.css` / `config.js`。GitHub Pages などで静的に配信する。
- **記録**：Google Apps Script（`gas/`）がスプレッドシートの「生ログ」に1行ずつ追記する。
- **解析**：同じ Apps Script が毎日「解析」シートを作り直す。生ログは書き換えない。

## 記録の仕組み

- カードを押した瞬間だけ記録する（ページを開いただけでは記録しない）。遷移先はこれまでどおり Google ドライブ。
- 記録する列：`時刻`（受信時刻）・`device_id`（ブラウザごとに `localStorage` へ発行するランダムな UUID）・`text_id`・`referrer`。
- `?from=wonder` 付きのリンクで一度でも来た端末は、以後 `referrer=wonder`。それ以外は `general`。
- 記録の時点では重複をはじかない。形式が壊れた送信（未知の `text_id` など）だけ捨てる。

## 解析のルール

同じ `device_id`・同じ `text_id` で、**最後にカウントした記録から90分以内**の再アクセスは同一利用とみなす。
あわせて 2・30・60・90・120・180 分でも数え直し（感度分析）、「◯〜◯回」の幅で出す。

「解析」シートの中身：

1. 期間（全期間・月別）× `text_id` × `referrer` ごとの、開いた件数としきい値別の利用回数と幅
2. 同じ端末・同じテキストで連続して開いた間隔の内訳（1分未満・1〜90分・90分超）

計算部分のテスト：`node tests/analysis.test.js`

## セットアップ

1. 個人の Google アカウントで新しいスプレッドシートを作る（共有はしない）。
2. 「拡張機能 → Apps Script」を開き、`gas/Code.gs`・`gas/Analysis.gs` を同名のファイルとして貼り付ける。
   「プロジェクトの設定」で `appsscript.json` を表示し、`gas/appsscript.json` の内容に置き換える。
3. エディタで `setup` を1回実行し、権限を許可する。「生ログ」「正解データ」「解析」シートと、毎日4時の解析トリガーができる。
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザーは「自分」、アクセスは「全員」。
   出てきた `…/exec` の URL をブラウザで開き、`ok` と表示されるのを確かめる。
5. `config.js` の `endpoint` にその URL を、各テキストの `url` に Google ドライブの共有リンクを入れる。
6. サイトを配信し、配布用のリンクには末尾に `?from=wonder` を付ける。

コードを直したら「デプロイを管理 → 編集 → 新バージョン」で更新する（URL は変わらない）。

## テキストを追加する

`config.js` の `texts` に1件足すだけでよい。Apps Script の変更・再デプロイは要らない。

```js
{
  id: "lego-new-car",        // 記録に残る text_id。英小文字・数字・ハイフン。一度使ったら変えない
  category: "レゴ",          // 新しい分類名を書けば、分類もそのまま増える
  title: "新しい車",
  summary: "一覧に出る1行の説明。",
  url: "https://drive.google.com/…",  // 空なら「準備中」と表示
},
```

一覧の説明（「レゴ3本・3Dプリンター2本」）、カードとタグの色、解析シートの行は自動で増える。

## 公開範囲

一般公開する（検索エンジンにも載る）。記録はカードを押したときだけなので、クローラーはほぼ数に入らない。
`?from=wonder` 付きのリンク経由で来た端末と、それ以外（`general`）は解析で分けて見られる。

## 精度の確かめ方

公開後2週間、自分が実際に使ったコマを「正解データ」シートに手で記録する（紙に書いて後から転記してもよい）。
列は `日付・コマ開始時刻・text_id・使った人数・使ったPC台数・メモ`。同じ期間の「解析」の90分の値と突き合わせる。
